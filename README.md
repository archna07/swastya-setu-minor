# Swastya Setu – Smart Healthcare Assistance Platform
> **Full-Stack Academic & Decision-Support Healthcare Web Platform**

Swastya Setu (*Healthcare Bridge*) is an integrated, full-stack healthcare web application connecting patients, hospitals, pharmacies, and emergency services into a unified portal. Built with a modular service-oriented architecture (Core PHP 8.x, MySQL 8.x, Python Flask AI Microservice, Leaflet.js, and Bootstrap 5), it delivers healthcare resource management, appointment scheduling, prescription tracking, and a clinical decision-support symptom analysis prototype.

---

## ⚠️ Medical & Regulatory Disclaimer

> **IMPORTANT CLINICAL NOTICE**: Swastya Setu is an educational prototype and decision-support demonstration tool designed for academic evaluation. It does **NOT** provide a definitive medical diagnosis, nor does it prescribe medications or specify dosages. Statistical pattern matches generated by the machine learning module reflect feature affinity within an experimental dataset and must never replace clinical assessment by a licensed medical practitioner. In case of acute respiratory distress, severe chest pain, loss of consciousness, or other urgent medical emergencies, immediately contact local emergency services (**108** in India, **911** in North America) or proceed to the nearest emergency trauma department.

## 🌟 Architecture & Core Modules

Swastya Setu follows a decoupled architecture separating frontend presentation, relational transactional persistence, and machine-learning decision support.

```
                      +-----------------------------+
                      |   Browser Client (User)     |
                      |  Bootstrap 5 / Leaflet.js   |
                      +--------------+--------------+
                                     |
                                     | HTTP / Session
                                     v
+------------------------------------+------------------------------------+
|                      PHP Web Application (Port 80/8000)                |
|  - Role-Based Access Control (Patient, Hospital, Pharmacy, Admin)      |
|  - CSRF Protection & Input Sanitization                                |
|  - Secure Upload Manager & Streaming Gateway                            |
+------------------+----------------------------------+------------------+
                   |                                  |
                   | PDO Prepared SQL                 | JSON REST API
                   v                                  v
+------------------+---------------+  +---------------+------------------+
|    MySQL Database (Port 3306)    |  |  Python Flask AI Service (5000)  |
|  - 14 Relational Tables          |  |  - Random Forest Classifier      |
|  - Composite Foreign Keys        |  |  - 36 Normalized Symptom Inputs  |
|  - High-Performance Indexes      |  |  - Emergency Red-Flag Detection  |
+----------------------------------+  +----------------------------------+
```

### 1. Multi-Role Authentication & Access Control (RBAC)
- **Role Isolation**: Strict separation across 4 roles:
  - **Patient / Citizen**: Book appointments, run symptom assessments, upload prescriptions, track medicine orders, broadcast 108 SOS.
  - **Hospital Admin**: Manage doctors, consultation schedules, appointment accept/reject queues, and live bed counts.
  - **Pharmacy Partner**: Review uploaded prescriptions, generate itemized medicine quotes, fulfill orders with live tracking.
  - **Platform Administrator**: Approve/reject hospital & pharmacy partner registrations, audit platform analytics, view all appointments, orders, and emergency logs.
- **Security Mechanisms**: Bcrypt password hashing (`PASSWORD_BCRYPT`), CSRF token verification on all state-changing requests, session fixation prevention (`session_regenerate_id`), and role-guarded route redirection.

### 2. Re-Engineered AI Clinical Decision-Support Service
- **Unified Centralized Symptom Catalog**: 36 standardized clinical symptoms categorized by organ system (Respiratory, Systemic, Digestive, Neurological, Metabolic & Urinary, Musculoskeletal, Dermatology) shared across Python ML, Flask REST API, PHP backend, and frontend JavaScript.
- **Multi-Model Evaluated Architecture**: Trained on verified clinical symptom-disease presentation matrices. Comparative evaluation includes Random Forest, Gradient Boosting, Decision Tree, Logistic Regression, and Naive Bayes with stratified 5-fold cross-validation.
- **Emergency Red-Flag Escalation**: Automatic detection of critical symptoms (Chest Pain, Shortness of Breath, Stiff Neck, Confusion) triggering prominent emergency warnings and direct 108 SOS dispatch escalation.
- **Medical Safety Rules**: Model score is transparently presented as pattern affinity; raw Random Forest probabilities are not misrepresented as clinical confidence. Prescription drugs and dosages are excluded from unvalidated predictions.

### 3. Hospital Locator & Real-Time Bed Availability
- **Interactive OpenStreetMap**: Integrated via Leaflet.js with dynamic geolocation marker placement (zero proprietary API key dependency).
- **Bed Inventory Tracking**: Tracks real-time availability across general, ICU, and oxygen-supported beds.
- **Specialist Appointment Booking**: Select doctors by medical specialty, consultation fee, date, and verified time slots.

### 4. Smart Pharmacy & Prescription Delivery
- **Secure File Upload**: Validates file extension, size (< 10MB), and verified MIME type (`image/jpeg`, `image/png`, `application/pdf`).
- **Access-Controlled Streamer**: Prescriptions are stored in a secured directory protected by `.htaccess` and served exclusively through `view_prescription.php` with patient/pharmacy ownership verification.
- **Itemized Quoting Workflow**: Pharmacists review prescription images, attach medicine line items with unit prices, and generate transparent quotes.
- **Cash on Delivery (COD) Ordering**: 4-stage live order progression (`order_confirmed` ➔ `preparing` ➔ `out_for_delivery` ➔ `delivered`).

### 5. Emergency 108 SOS Network
- **Instant Geolocation Capture**: Captures GPS coordinates via HTML5 Geolocation API.
- **Emergency Medical Passport**: Instant display of patient blood group, recorded allergies, and emergency contact details for rapid paramedic triage.
- **Trauma Center Mapping**: Direct links and hotline dialing for nearest emergency trauma hospitals.

## 🚀 Installation & Local Development Setup

### Prerequisites
- **PHP**: PHP 8.1 or higher (with `pdo_mysql`, `curl`, `mbstring`, `gd` extensions enabled).
- **MySQL**: MySQL 8.0 or MariaDB 10.4+.
- **Python**: Python 3.10+ (with `pip`).
- **Web Server**: Apache / Nginx / PHP built-in web server.

---

### Step 1: Clone the Repository
```bash
git clone https://github.com/your-username/Swastya-setu-app.git
cd Swastya-setu-app
```

### Step 2: Configure Environment Variables
Copy `.env.example` to `.env` and configure your credentials:
```bash
cp .env.example .env
```
Edit `.env`:
```ini
APP_ENV=development
APP_DEBUG=true

DB_HOST=localhost
DB_PORT=3306
DB_NAME=swastya_setu
DB_USER=root
DB_PASS=your_mysql_password

AI_SERVICE_URL=http://127.0.0.1:5000
```

### Step 3: Initialize the MySQL Database
Execute the CLI setup installer:
```bash
php setup.php
```
*This creates the database `swastya_setu`, builds all 14 relational tables, adds composite indexes, and configures secure demo accounts.*

### Step 4: Install AI Dependencies & Start Microservice
```bash
cd ai_service

# Install required Python packages
pip install -r requirements.txt

# (Optional) Re-train and evaluate ML models
python train_model.py

# Start the Flask AI Microservice
python app.py
```
*The AI microservice will start on `http://127.0.0.1:5000`. Keep this terminal window running.*

### Step 5: Start the PHP Web Server
Open a new terminal window in the project root:
```bash
php -S localhost:8000
```
Open your browser and navigate to:
**[http://localhost:8000](http://localhost:8000)**

## 🐳 Production Deployment with Docker Compose

Swastya Setu can be deployed in any cloud environment (AWS, GCP, DigitalOcean, Azure) using Docker Compose:

```bash
# 1. Clone repository
git clone https://github.com/your-username/Swastya-setu-app.git
cd Swastya-setu-app

# 2. Configure production environment
cp .env.example .env
# Edit .env with secure production database passwords and APP_ENV=production

# 3. Build and launch multi-container stack
docker compose up -d --build

# 4. Verify running services
docker compose ps
```

The stack provisions:
- `swastya_web`: PHP 8.2 Apache on port `80`.
- `swastya_ai_service`: Python Flask with Gunicorn (4 workers) on internal port `5000`.
- `swastya_db`: MySQL 8.0 on internal port `3306` with persistent storage volume.

## 🔒 Security Hardening Measures

- **No Public Access to Sensitive Files**: Apache configuration blocks web access to `config/`, `ai_service/`, `backups/`, and `tests/`.
- **Upload Isolation**: Prescriptions directory has script execution disabled via `.htaccess` (`<FilesMatch "\.(php|py|sh)"> Deny from all`) and index browsing prevented.
- **Session Protection**: Cookies configured with `HttpOnly`, `SameSite=Lax`, and `Secure` (over HTTPS).
- **Session Fixation Prevention**: Session ID regenerated upon every successful login via `session_regenerate_id(true)`.
- **Brute-Force Rate Limiting**: Exponential cooldown enforced on excessive failed authentication attempts.
- **CSRF Tokens**: Cryptographic token generation (`random_bytes(32)`) and constant-time validation (`hash_equals`) on all POST submissions.
- **SQL Injection Prevention**: 100% of dynamic queries use PDO prepared statements with bound parameters.
- **Two-Factor Password Reset**: Password recovery requires verified email and registered phone number matching to prevent account enumeration and takeover.
